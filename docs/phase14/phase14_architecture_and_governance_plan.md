## 1. Executive Summary & Epistemic Foundations

Phase 14 introduces the **AI Quantitative Research Layer** (`acash.research.ai`) to augment quantitative research with AI-driven hypothesis formulation, exploratory feature discovery, and automated institutional research reporting (Section 33).

In accordance with the foundational ACASH research philosophy:
$$\boxed{\text{DO NOT ASSUME AN EDGE. PROVE IT.}}$$
and the core Strategy Admission epistemic identity:
$$\boxed{\text{Observed Profit} \neq \text{Proven Skill} \neq \text{Structural Edge} \neq \text{Luck-Free Performance}}$$

Phase 14 establishes the strict epistemic boundary:
$$\boxed{\text{AI Output} \equiv \text{Unvalidated Proposal} \quad (\text{Never Validated Alpha}, \ \text{Never Trading Authority})}$$

An LLM or machine learning model has zero privileged knowledge of financial market dynamics. It possesses no authority to register a hypothesis, execute a trade, validate an empirical claim, certify a backtest, or allocate capital. Every output generated by Phase 14 enters the existing ACASH quantitative research, backtesting, and statistical validation pipeline as an unverified candidate subject to strict fail-closed rejection.

## 3. Scope Definition: Ownership Boundaries

### 3.1 What Phase 14 IS Responsible For
1. **AI Hypothesis Formulation Assistant (`acash.research.ai.hypothesis`):**
   - Ingesting market microstructure literature summaries, economic theories, or empirical anomaly descriptions.
   - Producing structured, pre-falsifiable `AIHypothesisProposal` objects.
   - Formulating candidate economic rationales, target horizons, expected sign directions, and pre-registered falsification bounds.
   - Attaching immutable cryptographic provenance metadata (LLM model ID, provider, prompt hash, completion hash, temperature, seed).
2. **AI Automated Research Report Generator (`acash.research.ai.reporting`):**
   - Synthesizing institutional-grade, audit-compliant research reports conforming to Section 33.
   - Ingesting sealed, verified ACASH evidence: `HypothesisSpecification`, `SearchTrialLedger`, `ValidationReport`, and `AlphaQualificationDossier`.
   - Strictly citing observed empirical facts with zero tolerance for hallucinated performance figures.
   - Enforcing clear structural demarcation: Observed Empirical Facts vs Model Interpretations vs Methodological Limitations.
3. **Exploratory Feature Discovery Assistant (`acash.research.ai.features`):**
   - Proposing mathematical transformations of microstructure variables (e.g. order flow imbalance ratios, micro-price drift, liquidity spread curves).
   - Validating symbolic expressions for strict causal and temporal point-in-time compliance ($t_{\text{feature}} \le T_{\text{decision}}$).
   - Rejecting forward-looking lookahead operators (e.g. unshifted lead terms, global whole-sample normalization).

### 3.2 What Phase 14 Explicitly Does NOT Own (Strict Non-Ownership Invariants)
- **NO Strategy Qualification Authority:** Phase 14 cannot qualify or admit strategies. Only Phase 8.5 `AlphaQualificationGate` and Phase 17 Sovereign Admission have this power.
- **NO Direct Hypothesis Registration:** AI proposals do NOT automatically become registered `HypothesisSpecification`s. Registration requires explicit human or sovereign policy acceptance.
- **NO Backtest Execution Authority:** Phase 14 does not run backtests or compute returns; it hands off specifications to Phase 5 `BacktestEngine`.
- **NO Statistical Testing Authority:** Phase 14 does not calculate DSR, PBO, or FWER; only Phase 6 `ValidationGate` holds mathematical authority.
- **NO Capital Authority:** Live capital authority is strictly **$0.00**.
- **NO Broker / Wire Authority:** Phase 14 has zero imports or dependencies on `acash.execution` or broker connectors.
- **NO Evidence Mutation:** AI cannot alter historical trial ledgers, modify backtest results, or generate synthetic return histories to pass gates.

### 5.1 AI Hypothesis Assistant (`acash.research.ai.hypothesis`)

#### Input Contract (`HypothesisFormulationRequest`):
```python
class HypothesisFormulationRequest(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    
    market_context: str = Field(min_length=10, description="Economic/microstructure context or observation.")
    target_symbol: str = Field(pattern=r"^[A-Z0-9_]{3,12}$")
    available_features: Tuple[str, ...] = Field(min_length=1)
    target_regimes: Tuple[str, ...] = Field(default=("MARKET_OPEN", "TRENDING", "MEAN_REVERTING"))
    max_proposals: int = Field(default=3, ge=1, le=5)
    researcher_id: str = Field(min_length=1)
```

#### Output Contract (`AIHypothesisProposal`):
```python
class AIHypothesisProposal(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    
    proposal_id: str = Field(pattern=r"^AI-HYP-[0-9a-f]{16}$")
    proposal_status: Final[str] = "UNVALIDATED_PROPOSAL"
    
    # Core Quantitative Hypotheses
    economic_rationale: str = Field(min_length=20)
    market_microstructure_mechanism: str = Field(min_length=20)
    invalidation_conditions: Tuple[str, ...] = Field(min_length=1)
    
    # Concrete Parameters
    target_symbol: str
    feature_dependencies: Tuple[str, ...]
    expected_direction: ExpectedDirection
    target_horizons: Tuple[int, ...]
    proposed_invalidation_criteria: InvalidationCriteria
    
    # Provenance & Lineage
    llm_provider: str
    llm_model_id: str
    prompt_template_sha256: str
    temperature: Decimal
    seed: Optional[int]
    generated_at_utc: str
    raw_response_sha256: str
```

#### Invalidation & Failure Rules:
- If LLM output fails schema validation, reject with `DataContractError`.
- If `expected_direction` is ambiguous or not in `ExpectedDirection`, fail closed.
- If proposed features are not subset of `available_features`, fail closed.
- If proposed `invalidation_criteria` contains infinite or negative values, fail closed.

### 5.2 AI Automated Research Report Generator (`acash.research.ai.reporting`)

#### Section 33 Compliance Specification:
Conforming to Section 33 and `docs/architecture/research_architecture.md`, the generated research report must contain:
1. **Executive Summary & Lifecycle Status:** Strategy ID, Hypothesis ID, AlphaLifecycleState, Hurdle Verdict.
2. **Economic Rationale & Hypothesis Lineage:** Original economic hypothesis, microstructure logic, registered author.
3. **Data Provenance & Timeframe Coordinates:** Training split, validation split, held-out OOS split dates and bar counts.
4. **Empirical Performance Evidence:** Table of observed returns, Sharpe ratio, Sortino, max drawdown, Calmar, profit factor.
5. **Statistical Validation Breakdown (Section 4 Compliance):**
   - Deflated Sharpe Ratio (DSR), $SR_0$, effective trials $K$, distribution skewness $\gamma_3$, kurtosis $\gamma_4$.
   - Probability of Backtest Overfitting (PBO) from Combinatorial Purged Cross-Validation (CPCV).
   - Family-Wise Error Rate (FWER) multiple-testing correction results.
   - Parameter perturbation fragility / cliff analysis.
   - Friction sensitivity matrix ($1\times$, $2\times$, $5\times$ spread + slippage stress).
6. **Economic Decomposition (Section 8.5 Compliance):**
   - Gross Trading Alpha, Realized Friction Drag, Net Trading Alpha (bps), Zero-Rebate Hurdle Excess.
7. **Observed Facts vs Model Interpretations:** Explicit visual demarcation separating deterministic empirical evidence from LLM commentary.
8. **Methodological Boundaries & Disclaimers:** Explicit non-guarantee statement (`Observed Profit != Proven Edge`).

#### AST Invariant Inspector (`CausalAstValidator`):
- Prohibits negative time offsets: e.g. `lead(x, 1)` or `x[t+1]` are hard-rejected.
- Prohibits whole-dataset normalization: e.g. `(x - mean(x)) / std(x)` where mean/std are computed across future periods. Only rolling or expanding windows (`rolling_mean(x, N)`) with $N \le t$ are permitted.
- Prohibits non-deterministic functions (e.g. `random()`).

## 8. Security, Provider Abstraction & Reliability Boundaries

### 8.1 Zero Secret Exposure & Key Hygiene
- API keys (OpenAI, Anthropic, Google Gemini, OpenRouter) must **never** be hardcoded, written to configuration files, or committed to Git.
- Keys must be resolved strictly at runtime via environment variables (e.g. `ACASH_AI_API_KEY`, `ACASH_AI_PROVIDER`).
- Mock providers are used exclusively during local test execution and CI; tests must never make outbound network calls.

### 8.2 Provider Abstraction Layer (`ILLMProvider`)
- System code depends only on `ILLMProvider` interface, never on vendor-specific SDKs.
- Providers implement:
  ```python
  class ILLMProvider(Protocol):
      async def generate_completion(
          self, prompt: str, system_prompt: str, config: LLMGenerationConfig
      ) -> LLMCompletionResponse: ...
  ```

### 8.3 Deterministic Provenance & Replayability
- Every prompt template is stored as an immutable constant with a pre-computed SHA-256 digest.
- Every LLM invocation records:
  `prompt_digest`, `completion_digest`, `model_id`, `temperature`, `seed`, `timestamp_utc`.
- If temperature is set to `0.0` and a seed is supplied, repeated runs against deterministic local models or cached responses produce reproducible proposals.

### 8.4 Rate-Limit, Timeout, and Fail-Closed Boundaries
- HTTP client configured with strict timeouts (e.g. 30s connection, 60s read).
- Bounded exponential backoff retry policy (maximum 3 retries) exclusively for transient network errors (HTTP 429, 502, 503).
- In the event of provider outage or timeout, the engine fails closed immediately, returning a structured rejection result without throwing unhandled exceptions.

## 10. Comprehensive Verification & Test Strategy

Prioritizing the non-negotiable testing order from `AGENTS.md`:
$$\text{Happy Path} \to \text{Boundary} \to \text{Malformed} \to \text{Contradictory} \to \text{Adversarial} \to \text{Permutation} \to \text{Numerical Stability} \to \text{Golden Reference}$$

1. **Schema & Serialization Tests:**
   - Verify canonical JSON serialization of `AIHypothesisProposal` and `AIFeatureProposal`.
   - Verify that extra fields are forbidden (`extra="forbid"`).
2. **Adversarial Malformed LLM Output Tests:**
   - Inject corrupted JSON, markdown code blocks wrapped in text, truncated completions, and invalid enum values.
   - Assert that parser fails closed with `DataContractError` and never crashes.
3. **Hallucination Rejection Tests (Section 33):**
   - Inject a report claiming Sharpe ratio 3.5 when the sealed `ValidationReport` has Sharpe ratio 1.8.
   - Assert that `ZeroHallucinationVerifier` detects discrepancy and rejects the report.
4. **Point-in-Time & Leakage Tests:**
   - Pass feature proposals containing `lead()`, future timestamps, or uncentered global statistics.
   - Assert that `CausalAstValidator` detects and rejects the lookahead leak.
5. **Gate Non-Bypass Invariant Tests:**
   - Verify that an `AIHypothesisProposal` cannot be directly passed to `AlphaQualificationGate` without passing Phase 5 backtest and Phase 6 statistical validation.
6. **Network & Provider Resilience Tests:**
   - Simulate HTTP 429 rate limits, HTTP 500 server crashes, and network timeouts.
   - Verify bounded retries and fail-closed termination.
