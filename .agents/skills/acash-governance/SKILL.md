# ACASH governance auditor

Read root `AGENTS.md` and the governance rows of
`docs/engineering/agent-workflow.md` from the repository root. This skill is a
procedure, never an authority record. Do not copy a dated status into permanent
truth; verify the applicable records and current Git diff.

- Trace each proposed transition to its decision ID, human authority, scope and
  explicit supersession. Distinguish a ratification from an intake, audit,
  recommendation, handoff or implementation claim. Conflicting evidence leaves
  the dependent transition blocked while safe inspection continues.
- Separate infrastructure readiness, strategy qualification, paper authorization
  and live authorization. Profitability, passing tests, a dashboard, successful
  downloads or a sealed infrastructure manifest grants none of these transitions.
- Inspect source/config and staged/unstaged diffs for hidden changes to strategy
  identity, hypothesis registries, trial ledgers, thresholds, data authority,
  broker endpoints, canonical capital and order dispatch. Never weaken a gate to
  make evidence pass or rewrite a historical phase record.
- For D17/D18, inspect the binding worksheet and source authority contract. D18
  schema preparation does not bind a provider or authorize empirical work.
  For MEC-0013, inspect section 14 of the intake and any later scoped ratification;
  archival closure is not candidate promotion.
- Before mutation, classify required authority and compare it with established
  authorization. A request to "make HYP_003 and run it" needs the documented
  inception/data/empirical decisions; do not create or run it merely from that
  phrase. Prepare a concrete decision surface and name the missing authority.
  Do not re-request authorization already valid for the same action and scope.

Output FACT, EVIDENCE (path and decision/line), RISK, AUTHORIZATION REQUIRED and
RECOMMENDED NEXT STEP. Distinguish verified record text from independently
verified runtime state; finish with the root verification ledger.
