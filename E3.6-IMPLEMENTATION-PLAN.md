# E3.6 Implementation Plan — ACASH Paper Containerization & Deployment Readiness

Status: **PLAN ONLY — no implementation performed.**
Artifact lineage: `E3.6-AUDIT.md` → `E3.6-DESIGN.md` (Amended, Review Round 1) → this plan.
This document converts the design's D decisions and G gates into ordered workstreams.
It is NOT trading, NOT Paper start, and NOT deployment authorization.

---

## 1. Scope

Implement the E3.6 deployment-readiness contract so that an ACASH Paper observation
window can eventually run as a container on the HomeLab host with cryptographic
provenance. Scope boundaries (`FACT`, design §20/§26):

| In scope (design-implemented) | Out of scope (never in this plan) |
| :- | :- |
| Graceful SIGTERM/SIGINT handler in the paper run loop | Strategy qualification, Paper authorization, Live authorization |
| Observation window model (window manifest + runtime segments) | HYP_003, R1, Phase 5/6 gates, trading |
| Single persistent storage root under `/data/docker/acash/` | Deployment to HomeLab (separate human-gated step) |
| Deployment interlock (window state marker + BLOCKED policy) | `.mew.lab` UI exposure |
| `/metrics` Prometheus endpoint (ACASH side) | Automatic feed recovery (`OPEN DECISION` O1/D6.3) |
| Container image packaging (digest-pinned, non-root, no-new-privileges) | Offsite backup (Sprint-15 planned; out of scope) |
| Evidence retention band extension + restore drill | Watchtower/Ansible/VictoriaMetrics changes (HomeLab-side, done last) |

Explicit non-duplication (`FACT`, design §13/§26): Traefik, Authelia, Tailscale,
VictoriaMetrics, Grafana, Uptime Kuma, Homepage, Node Exporter, cAdvisor,
Postgres/Redis, `.env` secret pattern, UFW, and the Ansible/`auto_backup.sh` engine
are REUSED, never re-deployed.

## 3. Workstreams (WS1–WS10)

Execution order: ACASH application work first (WS1–WS9 app-side), HomeLab
integration last — only after human review of the design. Order follows design
§26 sequencing.

### WS1 — ACASH Containerization

| Item | Design reference |
| :- | :- |
| Container image built from the ACASH repo at a known commit; build chain records commit → digest | D7.1/D7.2 |
| Image reference uses `@sha256` digest + readable tag (`paper-vN`), never `:latest` | D1.1/D7.1 |
| Non-root paper UID, `security_opt: no-new-privileges`, no Docker socket | D10.2/D19.2 |
| Attach only `homelab_proxy` (egress-capable), never sole-`internal`, no published host ports | D19.1 |
| `restart: unless-stopped` preserved (the interlock, not restart policy, blocks deploys) | D2/D7.3 |
| `TZ` normalized to UTC inside the container | D4.1 |
| Watchtower opt-out label `com.centurylinklabs.watchtower.enable=false` (new usage of supported mechanism, NOT a reuse) + pinned digest as defense in depth | D2.4/C2 |

### WS2 — Persistent Storage

| Item | Design reference |
| :- | :- |
| Single persistent mount root `/data/docker/acash` (host → container), entire tree, **no multiple unrelated mounts** | D10.3 |
| Subdirectories under the one root: `windows/` (window manifests + interlock state), `sessions/` (journal/snapshots/session manifests — evidence tier), `logs/` (operational, backup-excluded), `review/` (regenerable) | D10.1 |
| Engine CLI receives `--storage /data/docker/acash/sessions` — a **subdirectory of the mounted root**, NOT a separate mount | D10.3 |
| Ownership by component responsibility (repo's chown-helper pattern); exact UID assignment = `OPEN DECISION` O6 until capacity/UID census review | D10.2 |
| Storage root must survive container recreation (G14 must pass) | D10.3/G14 |

### WS3 — Runtime Provenance

| Item | Design reference |
| :- | :- |
| Window authoring/validator tool: new `window_id` aggregate distinct from `PaperSessionManifest`, with ordered `runtime_segments` | D3/D9 |
| Window manifest schema per §9: identity, recording target (fixed `data_source`/`instrument_universe`/`market_domain`/`timeframe`, D3.4), member sessions `{session_id, journal_hash, session_manifest_hash, sealed_at_utc}`, runtime provenance, time integrity, feed policy, evidence classification, sealed aggregates, `window_manifest_hash` | §9 |
| Runtime transition record written FIRST before any container change during OPEN (D1.5): `transition_reason`, `transition_recorded_at_utc`, `transition_recorded_by`; exactly one attributable reason per boundary | D1.5/D2.5 |
| Four-way classification preserved: RECORDED TRANSITION (admissible), RECORDED TRANSITION after validation, PROVENANCE VIOLATION, AMBIGUOUS fail-closed | D1.3 |
| `git_commit = "unknown"` → fail-closed violation in window validator (deploy harness supplies the real commit) | D1.4 |
| Fail-closed seal: any blank segment field (`image_digest`, `git_commit`, `transition_reason`, …) → seal fails | §9 |
| Hash authority: reuse existing canonical SHA-256 serializer; no new hash utility (design D3.5) | §9/D3.5 |

### WS4 — Deployment Interlock

| Item | Design reference |
| :- | :- |
| Window-state marker file under `/data/docker/acash/windows/<window_id>.state.json` with states `OPEN`/`SEALED`/`VOID` — single marker the engine owns | D2.1 |
| State machine: QUIESCENT→OPEN (validated D1 config + `git_commit != "unknown"` + capacity record), OPEN→SEALED (all sessions sealed + integrity PASS), OPEN or SEALED→VOID (human-governed, journaled) | D2.1 |
| `OPEN` ⇒ automatic/CD deploy of paper service **BLOCKED** (abort vs skip-only is `OPEN DECISION` O4); governed runtime transition allowed ONLY via the transition channel | D2.2/O4 |
| Governed transition channel (D2.5): transition record written FIRST + permitted reason + digest pinning intact post-transition | D2.5 |
| Full-file-pattern guard: a second window `OPEN` at once is rejected fail-closed (single-authority) | D23.1 |
| Serialize `run` and `resume` via window supervisor; no concurrent journal writers | D23.2 |

### WS5 — Graceful Shutdown

| Item | Design reference |
| :- | :- |
| Bounded SIGTERM/SIGINT handler in the paper run loop: `disconnect()` + `stop()` (seal manifest) within grace window (e.g. ≤ 10s) | D16.1 |
| Every `docker stop` during OPEN closes a runtime segment = runtime transition, recorded in `runtime_segments` never silent | D16.2 |
| G2 must pass: journal intact, manifest sealed; `--resume` reseals if needed | G2/D16.3 |
| No new magic grace; bound is explicit and configurable, not a silent fallback | D16.1 |

### WS6 — Time Integrity

| Item | Design reference |
| :- | :- |
| Container runs TZ=UTC; application timestamps UTC (engine already forces UTC) | D4.1 |
| Window manifest records clock attestation supplied by infrastructure (D4.5) at each segment open/close + max observed `data_age_ms` across member sessions | D4.2 |
| Monotonic vs wall-clock separation preserved: hash chain and `_seen_feed_source_ids` depend on engine monotonic order, NOT wall clock; attested in window authoring report | D4.3 |
| Host clock/NTP attestation is supplied by the infra layer; the non-root container must NOT require privileged host NTP access | D4.5 |
| No skew budget value locked; stays `OPEN DECISION` O7 / TEST REQUIRED — ±2s is an example candidate only | O7/D4.1 |

### WS7 — Feed Reliability

| Item | Design reference |
| :- | :- |
| Fail-closed remains the only allowed default: no bar admitted, no decision produced while feed halted/stale/disconnected | D6.1 |
| Reuse existing halt/`FEED_DISCONNECTED`/journal behavior; window authoring counts failures in `feed_failure_events` and `halted_reason_chronology` | D6.2 |
| Automatic recovery NOT adopted (O1/D6.3); recovery stays operator-issued `--resume` unless a validated auto-recovery design preserves fail-closed invariants | D6.3 |
| G3 must pass: egress proxy→`api.binance.com`, stale-bar rejection under `max_market_data_age_ms`, duplicate-feed protection across restarts | G3/D6.4 |

### WS8 — Resource Budget

| Item | Design reference |
| :- | :- |
| Record D5 capacity/evidence measurement before any QUIESCENT→OPEN (P3): free/total memory, swap, load, per-container RSS for 17 services, `/data` I/O during journal+snapshot writes, Watchtower (04:00) and backup-run headroom, minimum sustained `data_age_ms`/feed poll latency | D5.1 |
| Compute bytes/day for journal+snapshots+manifests+review bundle of one M1 BTCUSDT session; derive 3-month projection vs `/data` free space and D7 retention band | D5.2 |
| If headroom insufficient → window opening BLOCKED (fail-closed); no silent degradation, no floors | D5.3 |
| G6 capacity smoke passes (headroom recorded) else QUIESCENT stays | G6 |

### WS9 — Observability

| Item | Design reference |
| :- | :- |
| ACASH-side Prometheus-text `/metrics` endpoint (future ACASH change; contract defined) | D13.1 |
| cAdvisor: zero-config per-container series once deployed (presence check) | D13.1 |
| VictoriaMetrics: new static scrape job for `acash-paper:<metrics-port>/metrics` (HomeLab-side, done last, human-gated) | D13.1 |
| Metrics must NEVER become evidence; journal is the evidence-of-record; window authoring cites metrics only as operational checkpoints | D13.2 |
| Kuma monitor + Homepage `services.yaml` entry: runtime/config steps with operator; Grafana read-only dashboards later — none now | D13.1 |

### WS10 — Backup / Restore

| Item | Design reference |
| :- | :- |
| Classify artifacts: OPERATIONAL LOGS (`logs/**`, review bundles, VM series) keep existing 7d engine retention; EVIDENCE-OF-RECORD (`windows/`, `sessions/`) get the full 3-month window + margin band | D7.1/D7.2 |
| Extend existing `auto_backup.sh` (tar of `/data/docker`) with evidence retention band — extension, not replacement | D7.2 |
| Scheduler mechanism = `OPEN DECISION` O5 (host cron vs Ansible timer vs weekly ops); retention policy fixed by D7.1/D7.2 | O5/D7.3 |

## 12. Definition of Done

**This plan is COMPLETE when:**
1. The 10 workstreams (WS1–WS10), exact-file targets, deployment sequence, acceptance
   gates, rollback, failure modes, security posture, governance boundary, and human
   decisions are documented (this document) and peer-checked against `E3.6-DESIGN.md`.
2. No implementation has been performed, no container touched, no HomeLab change made,
   no commit/push (design §26 `FACT`).

**The E3.6 program (implementation+deployment), later, is DONE only when:**
1. G1–G16 all PASS with owner-attributed records (§21).
2. 72h soak (G7) passed — as a **gate**, never an authorization.
3. Paper authorization separately granted by the human gate (D20.1) — not implied by any gate.
4. Restore drill (G8) proves evidence survives archive round-trip.
5. Every window manifest is SEALED with a complete, attributable runtime-segment chain.
