## 4. Executive Summary

**ACASH Paper and HomeLab are structurally compatible for containerized hosting, with three integration consequences that must shape E3.6 design:**

1. **Provenance guard (RED-level unless designed for):** The deployed HomeLab stack runs `watchtower` at `0 0 4 * * *` with `INCLUDE_RESTARTING=true` against all containers. A paper container left with default labels would be **auto-updated and restarted at 04:00**, silently replacing the exact code that produced journal evidence. Any ACASH container **must** be excluded (`com.centurylinklabs.watchtower.enable=false` is the standard opt-out label) or evidence lineage is broken. (`FACT` Watchtower exists with those flags; the label mechanism is the standard Watchtower opt-out. `INFERENCE` on consequence.)

2. **Backup duration mismatch (YELLOW):** The existing backup engine archives only `/data/docker/*` (excluding `*/logs/*`) with a **7-day retention** and no verification stage. A 3-month Paper Review window over a journal/snapshot/manifest set **exceeds** what this backup can protect. The pattern is re-usable, but retention/scheduling/verification must be extended for evidence-class data (still not a second backup system if the existing engine is extended).

3. **No read-only UI or metrics endpoint exists today (YELLOW):** ACASH Paper is CLI-only (`python -m acash.paper run|status|integrity|review`). There is no Prometheus `/metrics` endpoint and no web surface, so VictoriaMetrics/Grafana/Uptime Kuma/Traefik/Authelia integration contracts are defined but **unimplemented**. Monitoring integration is a forward-looking contract, not a current capability.

Everything else aligns cleanly: the stack is a single `compose.yaml`, storage convention is `/data/docker/<service>/`, secrets live in host-only `/data/docker/.env`, ingress is Traefik+Authelia over Tailscale, and the ACASH runtime is a pure-Python (hatchling) wheel with no root/system requirements.

## 5. ACASH Runtime Audit

### 5.1 What must persist (evidence-class, three append-only artifacts per session)

The paper runtime writes exactly three persistent artifact files per session, all under the operator-supplied `--storage` root (`FACT`, `cli.py`):

| Artifact | Path convention | Written how | Integrity |
| :- | :- | :- | :- |
| Journal | `<storage>/<session_id>.journal.jsonl` | Append-only hash chain (`journal.py`), each event cryptographically linked (`previous_event_hash`), genesis `"0"*64` | `verify_integrity()`; reconciliation detects sequence gaps, dup event IDs, orphan orders, position/cash drift |
| Daily snapshots | `<storage>/<session_id>.snapshots.jsonl` | Append-only JSONL (`DailySnapshotStore`, `snapshot.py`) with `OBSERVED_PAPER_DATA_ONLY` governance label | Re-readable; corrupted lines raise |
| Sealed manifest | `<storage>/<session_id>.manifest.json` | Written once at `runner.stop()` (`runner.py:437-441`), JSON dumped with `default=str` | Contains `config_hash`, `journal_final_hash`, `return_sha256`, PAPER_ONLY enforcement |

- Chosen storage root is fully operator-controlled today: `--storage` flag, default `var/paper` (relative to CWD) (`FACT`, `cli.py:321`). **Container mount point can be arbitrary**; nothing is hard-coded to a desktop path.
- **Append-only truth**: journal + snapshots are the only evidence of record. Manifest is a seal, not a store — it captures final hashes. `FACT`.

### 5.2 What can be ephemeral / regenerated

- In-memory runner state (portfolio, position, cash), supervisor counters, health monitor state — all reconstructible from the journal.
- `runner.recover()` replays the journal and rebuilds `_seen_feed_source_ids`, kill-switch state, portfolio, and position (`FACT`, `runner.py`.
- Deterministic replay (`ReplayEngine`, `replay.py`) re-runs strategy decisions from journal bars and compares directions (replay status: PASS / PARTIAL / FAIL / INSUFFICIENT_DATA; no real orders, label `REPLAY_MODE_AUDIT_ONLY`).

### 5.3 Fail-closed behavior (confirmed contract)

- `PaperSessionRunner` rejects any config with `mode != PAPER_ONLY` (`FACT`, runner validation). `PaperSessionManifest` also rejects non-`PAPER_ONLY` (`manifest.py`).
- Stale bars → `MARKET_BAR_STALE`, no decision.
- Duplicate `feed_source_id` → `MARKET_BAR_REJECTED` / `DUPLICATE_FEED_SOURCE_ID`, no decision. Cross-restart dedup reconstructs from journal.
- Feed disconnect → supervisor halts; no decisions on disconnected data.
- Kill switch → halt; recovered on restart as `recovered_kill_switch`.
- Malformed provider payload → `MARKET_BAR_REJECTED`, pipeline untouched.
- Journal persistence failure → fail closed.
- Invalid/zero-variance math → `DataContractError` (strict fail-closed, no magic floors).
`FACT` (tests at `tests/unit/paper/test_paper_e35_real_alpha_feed.py`, `test_paper_e35_cli.py`, and `tests/integration/test_phase14_e35_real_feed_integration.py`).

### 5.4 Runtime provenance

- `config_sha256`, `return_sha256`, `journal_final_hash`, event `event_hash`, snapshot governance label, manifest seal, deterministic replay: provenance is chain-bound. `FACT`.
- Provenance granularity is per-session (`session_id`). A 3-month review requires **continuous session identity** across restarts (resume path is supported: `recover()` + `--resume`; session_id preserved). `FACT`.
- **Gap (container-relevant):** `cli.py` installs **no signal handlers**. A SIGTERM/SIGINT (e.g. `docker stop`) mid-loop terminates the interpreter without `runner.stop()`, so the manifest is not sealed and the final snapshot not captured. Journal integrity is unaffected, and `--resume` can re-seal, but a clean graceful-stop hook is missing for containerized operation. `FACT` (no `signal` import/usage in `cli.py`).

### 5.5 Container-friendliness

| Property | Status | Evidence/Reasoning |
| :- | :- | :- |
| Packaging | wheel via hatchling (`pyproject.toml`) | `[build-system] requires = ["hatchling"]`, packages `src/acash` |
| Python runtime | `>=3.12,<3.15` | `pyproject.toml`; host runs Python 3.14.6 (verified via test runs) |
| Dependencies | `cryptography`, `httpx`, `pydantic`, `pyyaml`, `structlog`, `duckdb`, `pyarrow`, `pandas`, `scipy`, `nautilus-trader==1.231.0` | Pure wheels on x86_64; no system libs at runtime |
| Image weight | heavy | pandas/pyarrow/duckdb/scipy/nautilus-trader are large; modest but non-trivial build |
| Root/system deps | none at runtime | feed is plain httpx to public Binance/Stooq endpoints |
| Filesystem | operator-controlled `--storage` only | no hard-coded paths; default `var/paper` relative |
| Network egress | required to `api.binance.com` (and optionally `stooq.com`) | NOT satisfiable on `homelab_internal` (internal:true); must attach to `homelab_proxy` or host |
| State model | single-process, single-writer, append-only files | container restart → `recover()` resumes; no shared-state locks across replicas (must be **one replica**, never scaled horizontally) |
| Graceful stop | missing signal handling | `FACT` gap (see 5.4) |
| Timezone | UTC internally; `TZ=Asia/Bangkok` convention exists in stack | `datetime.now(timezone.utc)` used in paper runtime |

`INFERENCE:` ACASH Paper can run as a container on HomeLab with a Python 3.12+ image, a single writable volume for `--storage`, egress on the proxy network, `restart: unless-stopped`, an `init`-style graceful-stop wrapper or short-poll sessions, and a Watchtower exclusion label. It is NOT multitenant-safe (single instance only).

### 6.9 Watchtower (`docker/compose.yaml` — explicit, separate section)

`FACT:`

- No `--scope`, no `--label-enable`, no per-service `com.centurylinklabs.watchtower.enable` anywhere in the repo today.

Answers for the Watchtower interrogation:
- *Could ACASH be automatically updated/restarted?* **Yes.** By default Watchtower updates every container whose image has a newer tag match; `INCLUDE_RESTARTING=true` even covers restarting containers. `FACT` (config) + `INFERENCE` (Watchtower behavior).
- *Would that alter Paper runtime provenance?* **Yes.** A mid-session image replacement changes the executed code; the sealed manifest records `git_commit`/`component_version` at session start but a silently replaced container runtime breaks "what code ran" evidence lineage for the live session. `INFERENCE`.
- *Are image tags/digests pinned?* **No.** No digest anywhere; `:latest` in use. Watchtower compares by tag. `FACT`.
- *Is controlled deployment possible with existing conventions?* **Yes, with one label** — the standard opt-out `com.centurylinklabs.watchtower.enable=false` per container (used by existing stacks for exactly this purpose). Also possible: pinning digests. `FACT` (mechanism exists) / `INFERENCE` (recommendation).

**Do NOT change Watchtower as part of this audit.** The container-level exclusion label is an ACASH-side (application) deployment decision to be made in E3.6 design — but it is a **required** one, not optional.

## 13. Recovery Audit

Compose semantics (`FACT`):
- `restart: unless-stopped` everywhere; daemon `live-restore: true` (containers survive Docker daemon restarts).
- `depends_on` only where they exist (grafana→vm; authelia/nextcloud→postgres/redis); no restart-condition/`restart_policy` gates, no healthcheck-based dependency.

Expected ACASH behavior per failure mode (all `INFERENCE` from ACASH code + compose semantics):

| Event | Expected behavior | Evidence class required |
| :- | :- | :- |
| Process crash | Journal partially appended; hash chain intact; manifest unsealed → `--resume` + `recover()` reseals | `recover()` + `review` output |
| Container restart | Same as crash; container orch restart → same path | — |
| Host reboot | `restart: unless-stopped` → container returns; `live-restore` irrelevant at host level; journal/volumes persisted on `/data` | — |
| Network interruption | Feed poll errors → `FEED_DISCONNECTED` → supervisor halts; no decisions on stale/disconnected data; `--resume` recovers | `FeedSupervisorStats.halted` |
| Feed interruption | Covered by stale + disconnect gates | journal events |
| Storage interruption | Writes fail → JournalEvent persistence failure → fail closed (`DataContractError`/storage error path); container should `exit` non-zero since state is unusable | fail-closed tests |

Preservation invariants: journal hash-chain, session identity (`session_id` preserved), manifest provenance (hashes), cross-restart duplicate-feed protection (`_seen_feed_source_ids` reconstructed), fail-closed gates — all preserved through restart per tests. `FACT`.
